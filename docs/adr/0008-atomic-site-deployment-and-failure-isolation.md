# ADR-0008：主站原子部署并隔离外部分发失败

- 日期：2026-10-26
- 状态：Proposed

## 背景

构建可能因单篇文章失败，第三方平台也可能长期不可用。如果直接覆盖线上目录，读者会看到半成品；如果外部分发与主站部署绑定，单平台故障会阻塞整个发布流程。

## 决策

主站先在独立候选目录或版本中完成内容校验和构建，全部成功后再原子切换公开版本。失败时保留上一成功版本并记录失败源 commit。

主站部署成功后，各文章、各平台账号的分发任务独立执行。主站成功不因外部失败回滚，某平台失败不阻塞其他平台。重放已成功部署的 commit 不重复创建分发对象。

主站归档与外部下架解耦，远端下架必须由显式操作触发并记录审计。

## 后果

- 线上版本始终对应一次完整成功构建。
- 读者可用性与第三方平台可用性解耦。
- 需要保留候选/旧版本和部署记录，占用一定存储。
- 用户可能看到“主站成功、某平台失败”的部分完成状态，UI 必须分目标展示而非给出笼统成功。

## 备选方案

- **原地覆盖构建**：实现简单，但构建中断会损坏线上站，拒绝。
- **所有目标放在同一事务**：外部网络系统无法提供这种原子性，且扩大故障范围。
- **主站删除时自动删除所有远端文章**：破坏性强且平台能力不一，拒绝默认执行。
