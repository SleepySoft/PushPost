# ADR-0003：分离期望状态与运行状态

- 日期：2026-10-26
- 状态：Accepted

## 背景

“作者希望发布”“主站已经部署”“平台已经收到文章”是不同事实。如果把它们合并到仓库的一个状态字段中，系统为了更新任务状态需要反复提交，容易形成提交循环，也无法可靠记录重试和错误。

## 决策

Git 保存期望状态，包括内容生命周期、计划发布时间和非敏感分发意图。服务端状态存储保存观察与执行结果，包括已处理 commit、部署状态、任务状态、远端对象 ID/URL、错误、尝试次数和审计记录。

凭据只进入密钥存储。同步服务不能因普通任务进度变化而反向修改文章仓库。

## 后果

- 发布意图可以代码评审，执行结果可以高频更新。
- 不会因为一次平台重试生成新的内容 commit 或再次触发主站部署。
- 需要在管理 UI 聚合两类状态，并明确展示各自含义。
- 状态存储需要备份；Git 本身不足以恢复远端对象映射。

## 备选方案

- **所有状态写回 metadata**：历史清晰但产生提交循环和高频噪声，拒绝作为运行状态方案。
- **所有状态只在数据库**：意图不可随文章评审和迁移，不符合 Git 事实源原则。
- **仅保留当前状态**：无法诊断历史部署和重试，不满足可追踪要求。
