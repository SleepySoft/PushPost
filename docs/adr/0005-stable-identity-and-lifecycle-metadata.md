# ADR-0005：使用稳定文章 ID 和显式生命周期元数据

- 日期：2026-10-26
- 状态：Accepted

## 背景

文章可能移动目录、修改文件名和 slug。若使用路径作为身份，主站历史和外部平台映射会失效。仓库已有 metadata，但其字段和语义尚未提供，需要避免未经确认地重新定义。

## 决策

目标仓库协议要求每篇文章具有唯一且稳定的 `id`，数据库以仓库 ID 和文章 ID 关联内容。路径用于组织和默认分类，slug 用于主站 URL，都不作为永久身份。

首版生命周期限定为 `draft`、`published`、`archived`。只有 `published` 文章可进入公开构建；`published_at` 为 `null` 或过去时间时可立即公开，为未来时间时到点前不公开。首次发布后该时间不被普通内容更新自动重置。

现有 metadata 在样本评审后通过显式迁移映射到目标协议，冲突必须人工处理。完整字段定义见 [内容仓库与 Metadata 设计](../content-repository.md)。

## 后果

- 移动文章不会丢失部署或平台关联。
- 需要一次性回填缺失 ID，并在每次同步校验重复 ID。
- 修改 slug 需要历史映射和重定向，不能简单视作新文章。
- `archived` 不自动表示远端删除，外部下架是独立操作。

## 备选方案

- **路径作为 ID**：实现简单，但重命名破坏所有映射，拒绝。
- **slug 作为 ID**：适合 URL，不适合永久身份。
- **沿用不明确的旧 metadata**：兼容性看似较高，但无法形成可靠验收规则。
