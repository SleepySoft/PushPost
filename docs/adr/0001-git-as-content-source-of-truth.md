# ADR-0001：以 Git 作为内容事实源

- 日期：2026-10-26
- 状态：Accepted

## 背景

系统同时包含公开网站、Decap、自研服务和外部平台。如果任一组件都能独立修改正文，就会产生多份事实源，导致冲突、覆盖和无法判断哪个版本有效。已有文章又位于 GitHub 私有仓库中，需要保留现有工作方式。

## 决策

GitHub 内容仓库是文章正文、媒体和公开元数据的唯一事实源。Decap、自研编辑器和普通 Git 客户端都通过仓库提交变更；数据库只保存可重建索引和运行记录，不提供绕过 Git 的正文修改入口。

每次发布必须关联确定的 commit。外部平台是内容的下游副本，不默认反向覆盖仓库。

## 后果

- 获得版本历史、差异、回滚、离线访问和可迁移性。
- 所有编辑入口可以共享同一内容校验和发布链路。
- 数据库正文索引可以重建，但远端映射和审计仍需备份。
- 在线保存需要处理 Git 冲突，不适合直接承诺实时多人协同。
- 大量二进制媒体可能增加仓库体积，需要后续媒体策略。

## 备选方案

- **数据库保存正文**：编辑方便，但破坏现有 Git 工作流并引入双写问题。
- **Git 与数据库双主**：无法可靠定义冲突优先级，拒绝。
- **第三方平台作为事实源**：受平台能力限制且内容迁移困难，拒绝。
