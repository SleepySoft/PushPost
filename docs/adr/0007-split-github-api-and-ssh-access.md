# ADR-0007：分离 GitHub API 编辑通道与 SSH 部署通道

- 日期：2026-10-26
- 状态：Accepted

## 背景

Decap 的 GitHub backend 通过 GitHub API 工作，而部署环境已保证私有仓库 SSH 鉴权。两者适合不同场景。若混用凭据，会扩大权限范围，并可能让浏览器或 Web 请求接触部署私钥。

## 决策

在线编辑使用 GitHub API，通过受控 OAuth/GitHub App 认证访问指定仓库。服务器内容同步使用 SSH Deploy Key 和受控工作区。两种凭据分开保存、授权和轮换，浏览器永远不能访问 SSH 私钥。

GitHub App、用户仓库权限和分支保护之间的关系必须在 Decap 技术验证中确认。需要 PR 工作流时，编辑器提交工作分支，合并到发布分支才触发公开部署。

## 后果

- 符合 Decap 既有集成方式，也利用部署环境已有 SSH 能力。
- 凭据泄露的影响范围更小，权限更易审计。
- 需要维护两套认证配置和故障排查路径。
- 如果编辑者认证必须依赖个人 GitHub 权限，非 GitHub 用户接入会受限制。

## 备选方案

- **所有操作使用服务器 SSH**：需要自研 Git 后端，且扩大 Web 服务风险。
- **所有操作使用高权限个人令牌**：权限过大且难以按仓库限制，拒绝。
- **浏览器持有部署私钥**：严重破坏安全边界，禁止。
