# ADR-0002：采用 Decap 与自研发布服务的组合

- 日期：2026-10-26
- 状态：Proposed

## 背景

首版需要尽快支持在线 Markdown 编辑和 Git 提交，但 Decap 本身不承担完整的网站部署、多平台任务、远端映射和运行审计。完全自研 CMS 又会延后核心发布闭环。

## 决策

采用 Decap 作为第一版内容管理界面，自研同步、校验、部署、分发、状态查询和审计服务。Decap 仅通过仓库协议影响内容，不直接调用平台发布接口，也不直接控制服务器部署。

自研编辑器作为独立演进方向，必须复用相同仓库协议和校验规则。替换编辑 UI 不改变发布架构。

## 后果

- 首版复用成熟 Git CMS 能力，开发集中在差异化需求。
- Decap 的目录 collection、字段和认证能力需要在真实仓库上验证。
- 任意目录、高级冲突处理等需求可能需要 Decap 定制或提前开发自研界面。
- 自研服务与 Decap 的字段定义需要保持一致，仓库协议是共同契约。

## 备选方案

- **完全自研 CMS**：控制力最高，但首版成本较大，暂不采用。
- **完全依赖 Decap**：无法覆盖同步任务和多平台分发。
- **TinaCMS/Keystatic**：可作为未来 UI 评估对象，但目前不引入第二套 CMS。
